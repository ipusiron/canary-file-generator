Canary File Generator

教育用のカナリアファイル・ハニーファイルを生成し、ハニートークンでどのファイルが開かれたかを突き止める流れを学べるツール

重要：本ツールは教育目的です。生成される認証情報はすべてダミーです。

カナリアファイル・ハニーファイルの生成

ファイル名と中身を決めてダウンロードすると、ファイルごとに一意のトークン（ハニートークン）を中に書き込みます。生成したファイルは「アラート」タブの台帳に記録され、そこから開封を擬似通知できます。入力はこのページの中だけで処理し、どこにも送りません。

    よく狙われるファイル名

    {{TOKEN}}と書いた場所にトークンが入ります。1つもなければ、末尾に「Ref: トークン」の1行を足します。{{DATE}}はその日の日付になります。

    ファイルを生成すると、そのファイルの開封を擬似通知できます。

    ※ 実際のネットワーク送信は行いません。画面の上で「検知」を擬似的に表示します。

    検知ログ（擬似）

    生成したファイルが開かれたことを、擬似的に記録します。実際に検知するには、ファイルの読み取りを記録する仕組みが要ります（座学タブの「6. 監視の例」）。

    このブラウザーでは保存できないため、記録はこのページを閉じると消えます。

    生成したファイル（台帳）

    ファイルごとに名前・トークン・生成日時を記録します。トークンがログや流出したテキストの中に見つかれば、どのファイルから出たかが分かります。

      検知ログ

      色分けは、通知からの経過時間です（1分ごとに更新）。

        このデータはブラウザーのlocalStorageに保存されます。機密情報は含みませんが、気になるときは使い終わったあとに消去してください。

        座学：カナリアファイル・ハニーファイル・ハニートークン

        1. 用語（本ツールでの区別）

        ダミーファイル
        代用品・テスト用のファイル。誘引や検知の仕掛けは持たない
        ハニーファイル
        攻撃者を誘引する「餌」のファイル。本ツールでは、検知の仕掛け（監査ログなど）を別に用意するものをこう呼ぶ
        カナリアファイル
        触れられたら検知できるように、誘引と仕掛けを組み合わせた偽ファイル
        ハニートークン
        正規の業務では使われないはずの偽データ（資格情報・鍵・文書・識別子など）。使われた時点で、漏洩や不正利用の確証になる

        用語の境目は文献によって違います。Yuillほか（2004）はハニーファイルを「攻撃者が触れるとファイルサーバーが警報を出す餌のファイル」と定義し、検知の仕組みまで含めています。Spitzner（2003）はハニートークンに、資格情報だけでなく文書なども含めています。

        2. ハニートークンの考え方

        ハニートークンそのものはただのデータですが、正規の文脈の外で使われた時点で、不正なアクセスがあったと分かります。たとえば、権限を持たないクラウドのアクセスキーを置いておき、それが使われたことをクラウドの監査ログで知る方法があります。本ツールのトークンも、ファイルごとに一意の識別子です。ログや流出したテキストの中に見つかれば、どのファイルから出たものかが分かります。

        3. 歴史

        • 1988年：Clifford Stollが、侵入者の目を引く偽の文書を置き、誰が読んだかを記録した（論文「Stalking the Wily Hacker」、翌年に書籍『The Cuckoo's Egg』）
        • 1992年：Bill Cheswickが、侵入者に偽のpasswdを渡して行動を観察した記録を発表した（「An Evening with Berferd」）
        • 1999年：The Honeynet Projectが発足した
        • 2003年：Augusto Paes de Barrosが「ハニートークン」という語を使い、Lance Spitznerの記事で広まった
        • 2004年：Yuillほかが、ファイルサーバーで警報を出すハニーファイルを論文にまとめた
        • 2009年：Bowenほかが、偽の認証情報とビーコンを入れたデコイ文書で、内部の攻撃者を検知する仕組みを発表した
        • 2013年：JuelsとRivestが、偽のパスワード（Honeywords）でパスワードの漏洩を検知する方法を提案した
        • 2015年：ThinkstがCanarytokensを公開した

        詳しい年表（docs/HISTORY.md）

        4. 使われる場面

        • ハニーポット：confidential.docxのような名前のファイルを置き、開かれたことを検知する
        • マルウェア解析：サンドボックスにハニーファイルを置き、マルウェアがどのファイルを探すかを観察する
        • ランサムウェアの検知：ドライブの直下などにカナリアファイルを置き、書き換えを検知する。一部のEDR（Elastic Defend、Check Point Harmony Endpoint、Huntressなど）は、この仕組みを製品に組み込んでいる
        • サーバーへの侵入の検知：.ssh/id_rsaのような名前のファイルへのアクセスを検知する
        • CTF：偽のフラグや、回り道をさせるファイルで出題する

        5. 発展

        • 通知：開いたときに外部へ通信させて知らせる（本ツールは通信せず、画面の上の擬似通知だけ）
        • 署名：正規のファイルには署名を付け、カナリアには付けない。真正性を確かめれば区別できる
        • 多層配置：場所や種類を変えて置き、どこまで入り込まれたかを見る

        6. 監視の例

        ファイルを置くだけでは検知できません。ファイルの読み取りを記録する仕組みと組み合わせます。

        Linux（auditd）：次のルールで、ファイルを読み取りで開いた操作を記録し、キー（canary）で検索します。-wと-pの書き方は互換のためのもので、manでは非推奨とされています。

        auditctl -a always,exit -F arch=b64 -F path=/srv/share/passwords.txt -F perm=r -k canary
ausearch -k canary -i

        Windows：「オブジェクトアクセスの監査」の「ファイルシステム」を有効にし、ファイルのSACLに読み取りの監査を足すと、開かれたときにイベント4663が記録されます。Sysmonには、ファイルの読み取りのイベントはありません。

        macOS 13以降：OSに付属のesloggerで、Endpoint Securityのファイルを開くイベントを記録できます（root権限とフルディスクアクセスが必要）。

        7. 実務で使うとき

        本ツールが作るファイルは、セキュリティツールの誤検出を避けるため、偽物であることを明示しています。実際のハニーファイル・カナリアファイルとして使うときは、生成したファイルを下書きにして、次の点を調整します。

        • EXAMPLE_・DUMMY_・[EDUCATIONAL ONLY]などの標識を外す（トークンは残す）
        • 組織名・サーバー名・日付などを、置く環境に合わせる
        • ファイルの権限をそろえる（例：SSHの秘密鍵は600、passwdは644）
        • 読み取りの監視と通知を設定する（6. 監視の例）
        • 本物の形式の鍵を置くと、GitHubなどのsecret scanningで発行元に通知されることがある。形式を崩した値のままにするか、置く場所を確かめる

        置く環境に合わせて本物と見分けがつかないものほど、攻撃者は手を出しやすくなります。
